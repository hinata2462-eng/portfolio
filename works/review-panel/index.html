10の視点の審査パネル（G10・DECAGON）

作った物の品質や、売り方の判断を、10人の専門家役がそれぞれの視点から別々に審査する仕組みです。G10は「完成させて売るところまで運ぶ」側、DECAGONは「止めて確かめる」側のチームです。

Codex（チームの設計）Claude Code（審査の実行）人物図鑑
見本：架空の料理教室の、架空の申し込みページを審査した例です

困りごと

AIに「これでいい？」と聞くと、たいてい褒めるか、目についた所を少し直すだけです。何を基準に合格にしたのかも残りません。お金や公開に関わる判断ほど、思い込みや言い過ぎを、出す前に止める仕組みが必要でした。

仕組み

どのAIで作ったか：2つのチームの人物と決まり（人物票・人物図鑑・審査の用紙）は、Codex（OpenAIのAI）で作りました。フォルダの常設の指示は Codex が読む決まりのファイル（AGENTS.md）で、起動の手順にも「Codexへ次のように依頼する」と書いてあります。

そのあと実際に審査を回す時は Claude Code を使い、審査する物に合わせた10の視点を、同時に別々のAIとして動かしました。

審査の進め方

  1. 問いを1文にする誰に、何を、どの条件で、なぜ今やるのか。問いが2つあれば分けます。
  2. 証拠に印を付ける確認済み／仮説／不明／古い、の4つ。分からない所を、0や当て推量で埋めません。
  3. 10人が別々に審査するほかの人の最初の意見を見ずに、自分の視点だけで「合格・条件つき・不合格」と理由を出します。
  4. 前提をぶつけ合う市場と商品、広告と計測、ブランドと安全、の組で、お互いの前提・計算・証拠を突きます。人ではなく中身を攻めます。
  5. 重い指摘を確かめ直す反証の係が、重い指摘を本当にそうか実物や計算で確かめ、外れていれば判定を下げます。
  6. 致命的な問題は点数で相殺しない1つでも残れば進めません。まとめ役が「進める／条件つきで進める／保留／やめる」を出します。

2つのチームの違い

G10（上のチーム）

選ぶ・作る・売る・測る・直す、を利益が残るところまで運ぶ実行役。人に判断を求めるのは、おすすめ付きで3件まで。今日やることは優先順で5件まで。

DECAGON（審査のチーム）

大事な判断を10の独立した視点で審査し、思い込み・使いすぎ・根拠のない表現を止める役。得意は判断の質と反証、苦手は毎日の実行。

Claude Codeでの使い方

たとえばWebサイトなら、スマホでの見え方・速さ・使いやすさ・コードの質・計測・申し込みまでの流れ・デザイン・不具合への強さ・文章・受け入れ条件の10の視点で審査しました。

見本

審査の対象（架空） 町の料理教室「体験レッスン」の申し込みページと、広告の計画 問い：このページのまま、来月から広告を出してよいか。
合格 3条件つき 5不合格 2
席（DECAGON）判定ひとこと理由
D01 峰岸 遥市場の耳条件つき「平日の昼に通いたい人がいる」の根拠が、先生の感覚だけ。問い合わせの記録を10件見たい。
D02 相馬 結顧客の代弁者合格「包丁が苦手でも大丈夫」の一文が、初めての人の一番の不安に答えている。
D03 鷹野 玲値付け審問官条件つき不合格1回1,500円は材料費と片付けの時間で赤字、と見た。確かめ直すと小さく黒字。定員は書くこと。
D04 紫藤 奏記憶の編集者条件つき写真が素材集のよう。先生の手元と教室の実物の写真に替えたい。
D05 速水 鋭投資判定者合格広告は1万円まで・2週間・申し込み0件なら止める、と損の上限が決まっている。
D06 七瀬 灯表現の批評家条件つき見出しが「心を込めた料理を」で、何の教室か3秒で分からない。
D07 春日 透導線解剖医不合格申し込みまでに日付・コース・人数の3つを選ばせている。体験は日付だけでよい。
D08 城戸 剛商談の現実主義者合格体験のあとに「次の回の予約」を案内する流れがある。
D09 冬月 計因果の番人条件つき申し込みが、どの広告から来たかを分けて数える設定がない。
D10 御影 律境界の判事不合格「必ず上達します」は言い切りすぎ。食物アレルギーの注意書きもない。

反証の係が確かめ直したこと

  • D03 の「赤字」：計算をやり直すと、材料費が二重に数えられていた。片付けの時間を入れても小さく黒字 → 不合格から条件つきへ下げた。
  • D10 の「言い切り」：ページの文面に実際にあった → 致命的な問題として残す。

まとめ役の結論

条件つきで進める

  • 直すまで出さない：「必ず上達します」を消し、アレルギーの注意書きを足す。
  • 直してから広告：申し込みで選ぶのは日付だけにする。見出しを「何の教室か」が分かる一文にする。広告ごとに申し込みを数える。
  • 見直す時：申し込みが10件たまった時か、2週間後。

工夫したこと

  • 10人は、ほかの人の最初の意見を見ずに審査します。先に強い意見を読むと、ほかの人が引っぱられてしまうからです。
  • 致命的な問題（根拠のない実績や保証、許可のない素材、損の上限が分からない広告など）は、ほかが高得点でも相殺しません。
  • 重い指摘ほど、別の係が確かめ直します。間違った指摘で良い物を止めないためです。
  • 人物はすべて架空のAIの役で、経歴は「判断のくせと話し方をぶらさないための設定」と明記しています。実在の人や実績のふりはさせません。

結果

2026年7月31日に、Codexで2つのチームを作りました。それぞれ10人分の詳しい人物票と人物図鑑のページ、審査の用紙（G10は6種、DECAGONは3種）、自分たちで行った監査の記録3本ずつがあります。

先に作ったDECAGONの自己監査では、判断の質は高い一方で「毎日の実行の速さ 62点」「人の負担 66点」と弱点が出ました。そこを上回るように、実行役のG10を上のチームとして作っています。8月からは Claude Code で、デモのWebサイトの公開前の審査、漫画づくりのスキルの検証、音楽動画の企画づくりに使いました。

人物はすべて架空のAIの役です。審査の見本の料理教室・ページ・数字は架空です。
